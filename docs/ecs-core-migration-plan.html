ecs_core 整理与架构优化 · 迁移方案

目标不是重写，而是把已验证的行为固定住，再一点点把边界做清楚：内容数据、纯规则、ECS 运行时各归其位；每一阶段都可单独回退。

1原则：先把"整理"定义成可验收的行为

四条硬规则

  • 行为冻结优先：纯整理阶段（M0–M2）不改变玩家可观察结果；以现有测试与 soak 作为回归基线。
  • 一阶段一提交：每阶段结束时工作树干净、docs_check 通过、gate 全绿；出问题 git revert 整阶段回退。
  • 单一写者不变：整理不能把"唯一定案/唯一落地/唯一装配"拆成两条路径。
  • 不为拆分而拆分：不新增 crate（除非判据满足）；不为并行而并行。

验收口径

  • 行为不变阶段：测试数只增不减，soak 6 种子「异常：无」。
  • 新增能力阶段：先有测试与 DESIGN 条目，再有实现。
  • 每个阶段写一行 REFACTOR.md；涉及取舍的写 DESIGN；数值只进 GAME.md。
  • 架构守卫：content/ 不得出现 bevy_ecs（元测试）；调度全部集中在三处注册文件。

3借道完成的架构优化（不是额外工程）

A1 内容边界 M1

零 bevy 的 content/ 模块 + 元测试守卫。
  • 注册表/词表/装配器获得独立解释空间；为将来 dungeon-content 留接口。
  • 先不做 crate 拆分（判据见拆分研究）。

A2 调度分组 M2

20 系统单链改为 5 个命名 SystemSet 链（战斗 / 效果 / 成长 / 空间 / 收口）。
  • 突破 bevy 元组上限，后续加系统不用再嵌套妥协。
  • 顺序仍集中在 system/mod.rs，可读性提升。

A3 仲裁归约化 M2

生成器写意图候选 → 纯 reduce 选胜者 → 单写者物化。
  • 落选者不再建实体；仲裁成为可单测纯函数。
  • 故意不上并行/原子：当前规模收益为微秒级，确定性优先。

A4 相内订阅者 M3

统一伤害出口扩为"事件 + 消费者"：仇恨、武器经验、on-hit 从 apply_damage 抽出。
  • 保留流水线主干；只把扇出改成订阅，避免事件驱动世界。
  • 每个消费者仍在固定相位内显式注册，顺序可测。

A5 单一能力来源 M3

怪物能力与状态施加表由模板数据统一生成，删硬编码。
  • Ability → Can* 映射集中；物种→状态表进内容数据。
  • 新增能力只改数据 + 一个枚举分支。

A6 地图配置化 M4

Map 运行期尺寸、Layer/Block 资源、切图服务。
  • 默认 80×60 保持现有测试；128×128 只在新区块测试启用。
  • 单块模式先行，2 块验证后再铺开。

A7 存档差异最小化 M5

V6 存层/块坐标与访问集；区块内容默认"离开重置"。
  • 不存块内实体，只存必须跨块保留的玩家状态与开关。
  • 层尾门作为区块坐标的特例，不新增独立门系统。

A8 时间表单一来源 M6

把 TIMING v2 的 AV/伤害系数落进 balance.rs 与数据表。
  • 武器 AV、怪物攻击 AV、效果时长从一处读取；模拟脚本复用同一套常量。

A9 契约与焦点状态 M8

SceneFrame.focus 增加锁定态，契约升 v9。
  • UI 状态继续留在 presentation，不进 ECS 世界。
  • headless 测试覆盖焦点移动/锁定/确认。

为什么先整理内容边界（M1）再做玩法（M4–M8）： 后续每个玩法阶段都会新增数据字段（状态/武器/怪物/地块）。如果内容定义还混在运行时文件里，每加一个字段都要动 Component 旁边的代码，等于把债务滚进新功能；先把边界立起来，后面每个阶段只碰自己那一层。

4阶段计划（串行，每阶段独立可回退）

总计约 15–20 个工作日；M0–M2 为纯整理（行为冻结），M3 起按内容 v1.2 已定稿的范围落玩法，未定内容不实现。

5顺序与并行

严格串行：M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8 → M9。

可并行的小任务（同阶段内）：文档更新、测试文件拆分、死代码清理可与相邻阶段并行做；但同一文件不允许两阶段同时写。

可省略/后置：M5（存档 V6）可以等 M4 稳定后再做；M8 可以前移到 M6 之前，如果 UI 反馈优先；M7 可以拆成 M7a（品质+气力）与 M7b（闪避+督军）。

6不做什么（明确边界）

不做 crate 拆分 按判据

  • M1 只做模块边界；`dungeon-rules` / `dungeon-content` 等 Step 2/3 判据满足再议。

不换并行/原子仲裁 明确

  • 只做归约化；确定性优先；规模收益微秒级。

不做纯发布-订阅主干 明确

  • 只在相位内做消费者；时间/仲裁/定案/落地仍走流水线。

不做未定稿内容 内容约束

  • 魔法（第二层）、友好生物、区块网 >2 块、更多效果类型一律排在 M9 之后，按用户拍板再做。
