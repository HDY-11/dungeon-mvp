②行动流水线 ActionPocSchedule · 6 阶段

Generate

只 spawn 候选，不写 actor 状态 player_action_generation wait_generation chase_generation wander_generation flee_generation

Arbitrate

每个 actor 挑一个候选转正 action_arbitration_system 优先级：Player(-1000) < Flee(-200) < Chase(-100) < Wander(-50) < Wait(0)

Tick

推进 AV；归零插 Ready tick_action_timers_system 最小正剩余 AV → 推进 WorldClock.total_av / last_step_av

Validate

定案 + 占用预留（串行） validate_move validate_basic_attack validate_cast validate_throw validate_chase validate_flee validate_wander

Execute

只落地，不再判定 settle_action_system 写 MoveTarget → Position；
其余目标 → 发意图事件

Complete

回收行动实体、回 Idle/Failure action_completion_system
行动实体上的组件： ActionOf(actor) ActionPriority ActionSource ActionName ActionTimer ActiveAction Candidate Ready 载荷： WaitMoveBasicAttackChaseFleeWanderCastSpellThrowAction 定案： MoveTargetAttackTargetCastTargetThrowTarget

actor 侧的状态只有 Idle / Active / Failure（加 ActionTimer）；行动实体由 ActionOf → ActionChildren 关系挂载，actor 死亡时级联回收。

③核心结算链 CoreSettleSchedule · 20 + 1 系统

伤害落地 resolve_attack→ apply_damage→ resolve_spell→ resolve_throw→ consume_thrown_item
效果生命周期 advance_effect_durations→ poison_tick→ poison_apply→ expire_effects
死亡 / 成长 check_death→ apply_exp→ refresh_vitals→ mana_regen
观测派生 fov→ update_map_memory→ update_visible_memory→ rebuild_occupancy→ rebuild_cell_effects→ heal_spring
仇恨 / 收口 threat_system→ update_events_system （必须最后：交换事件双缓冲，否则跨轮残留）

伤害来源统一走 DamageTakenEvent：近战 / 法术 / 投掷各发一次，仇恨系统只订阅这一个出口。死亡判定在效果结算之后，保证“被毒死”“被投死”都在本轮收口。

⑤关系、数据、资源与事件

关系组件（归属）

  • ActionOf → ActionChildren：行动子实体，linked_spawn 级联（actor 死亡不留行动实体）。
  • EffectOf → OwnedEffects：效果子实体，linked_spawn 级联（效果随载体死亡一起清）。
  • Container.slots: Vec<Option<Entity>>：身体 / 行囊 / 尸体的“持有”，不级联——装备卸下后物品仍在。
  • GroundItemAt：地面物品只标格子，没有 Position，不参与占用图。

数据注册表 → 装配

  • assets/items.json（schema 9）→ ITEMS → Item{id}.def()：parts 决定组件；spawn_item_assembled 是唯一装配桥。
  • assets/spells.json（schema 1）→ SPELLS → SpellBook{ known } / CastSpell{ spell }。
  • MONSTERS（Rust 静态表）→ MonsterKindId → 模板决定数值、Ability 列表决定 Can* 组件、掉落与尸体装备。
  • ContainerDef：BODY（7 槽）/ TRAVELER_PACK（12 槽）/ CORPSE（4 槽）。

资源与事件

  • 资源：Map / MapSeed / FloorNumber / GameRng / MapMemory / VisibleMemory / OccupancyMap / CellEffects / EventLog / TurnManager / WorldClock / PlayerSpawn / StairsPos / PlayerActionRequest。
  • 事件：AttackIntent → AttackEvent → DamageTaken；SpellIntent、ThrowIntent；Death / LevelUp；ActionSucceeded / ActionFailed。
  • 事件只做“意图/结果”传递，不在事件里改世界；每轮末尾由 update_events_system 统一交换缓冲。
