## 状态词

- **草案**：我整理的初步内容，用户还没看/没表态
- **待拍板**：问题已摆到用户面前，等回答
- **已拍板**：用户明确说过，记录轮次与原话要点（`R{n} 用户说：「…」→ 结论：…`）

## 内容设计的硬约束（来自既有 DESIGN，别违反）

- 物品 = 蓝图 + parts（DsnE27）；数值只走 `StatId` + `Modifier`；类别用 tags。
- 品质六档且实例不改品质（DsnE23）；物理伤害五域（DsnE24）。
- 数据形状已固定：新内容优先用现有 parts/effect 表达；需要新字段/新效果/新 AI 原语 → 写 RULES.md「需要骨架」并 3 行内报 lead。
- 内容生成必须确定性：层内容由 (seed, floor) 完全决定；随机只从 GameRng。
- 法术体系将按用户原始设计重做（DsnE26 开放问题 1–7），不要沿用当前简化公式。
- 当前「一层 = 一张 80×60 地图 + 楼梯」；第一层的区块网结构（m00314）是架构级新骨架，已在 RULES.md R3 登记。

## 工作流程

1. 用户说 → 我问清（每轮 2–4 个关键问题）→ 一个话题聊完或用户说「记一下」再落文档（状态 + 出处）

3. 需要新骨架能力 → RULES.md「需要骨架」+ 3 行内报 lead
