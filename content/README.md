## 状态词

- **草案**：可讨论、可推翻。
- **待拍板**：已给选项与推荐，等用户决定。
- **已拍板**：记录用户原话要点 + 条目号（CONTENT R#）。

## 硬约束

- 只写 `content/`；不动代码、`ecs_core/assets/*.json`、DESIGN/GAME/RULE 文档；不跑 cargo/gate；不 git 提交。
- 数值全部 [试调]，只进内容草案/GAME，不进 DESIGN。
- 需要新骨架时写进 `RULES.md` §R3，并报 lead（简短：要什么/为什么/影响文件）。
- 设计先行；与既有 DESIGN 冲突处必须标出，不默默照做。
- 用户拍板；AI 只给选项与推荐。

## 工作流程

- 一个话题聊完、或用户说「记一下」时，再落文档；**不每轮写文件、不每轮报 lead**（用户明确要求）。
- 引用规范：只引用文档与条目号（`CONTENT.md` R#、`LAYER1.md` §、`RULES.md` §），**不写聊天消息号**。
- 内容优先级（当前）：**敌怪候选与特色（用户设计）** → 第一层细化（区块图/密度）→ 战力与构筑闭环 → 魔法（第二层）→ 叙事节拍表。
