### R3.1 层内区块系统（#11）评估备注（lead）

- **地图生成**：现状一层=一张 80×60 `Map`+单次生成器+楼梯，FOV/占用图/格效果/寻路/相机全按单图工作。
  - 路线 A（推荐）：**每区块一张 Map + 连接口切图**——单图系统基本不改，约 2–3 轮（区块图、连接口、切换入口、存档坐标）。
  - 路线 B：连续滚动——换世界坐标系（渲染/相机/寻路/FOV/存档同时改），成本高一个数量级，第一章不做。
- **存档与层边界**：V5 只存 `map_seed + floor + 玩家状态`，地图按 `(seed, floor)` 确定性重放。区块化后必须增存「当前区块坐标 + 区块图 seed」；每个区块的怪物/物品/事件 RNG 从 `(seed, floor, cx, cy)` 派生（不能沿用每层一条 RNG 流，否则进入顺序改变内容、读档不可复现）。
- **状态保留**：离开再回来保留状态 → 需要区块级 delta 存档（chunk_id+变更）+ 卸载休眠/回收 = 第二个新存档层，工作量最大。**第一章建议先做「离开重置/只保留一次性开关」** → 存档只多两个坐标字段，成本近零。
- **依赖排序**：区块系统先动地图生成与 `world/floor.rs` 同级入口，其余系统保持「一次只看当前 Map」。
- **结论**：架构级 + 第一个新存档层；第一层内容定稿并出现「箱庭/多区块」实际需求后再立项。v1 采用**单图深度分区**（§R6 #1），不做区块网。

### R4.1 OnHitEffect 数据结构（v1 必做，lead 已同意）

- 统一枚举（武器与怪物复用）：`Stun` / `Bleed` / `Poison` / `SlowMove`；每条带 `trigger = Chance{p} | Threshold{max_hp_pct}`、`duration_av`、`magnitude`、`tick_av`（DoT）、`max_stacks`。
- 怪物侧：`MonsterTemplate.on_hit_effects: &'static [OnHitEffect]`；`poison_apply_system` 泛化为 `apply_on_hit_effects_system`（读攻击者模板，不再硬编码 Scorpion）。
- 武器侧：新 weapon part 携带同一 `OnHitEffect` 列表；`weapon_on_hit_system` 接在 `apply_damage_system` 之后，消费 `DamageTakenEvent` + 主手 `Weapon`。
- **武器伤害系数（v2 校准新增，小骨架）**：weapon part 新增 `damage_multiplier: f64`（默认 1.0，serde；items schema 升 **10**），进 `rules::damage` 作第六乘区：`最终 = max(1, 基础 × 增伤 × 暴击 × 护甲 × 抗性 × 武器伤害系数)`；`MeleeInput` / `ThrownInput` 透传。方案 B 暂定（匕首 0.55 / 剑 1.0 / 锯齿 1.0 / 锤 1.5 / 重剑 1.6），方案 A/B 二选一见 `TIMING.md` §0/§2。
- 成本估算（lead）：约 0.5 天。
- **实现口径（lead 2026-11-11 确认）**：怪物攻击 AV 用 `MonsterTemplate.weapon_speed_ms: Option<f64>`（None→300），`AV = weapon_speed_ms.unwrap_or(300.0) / attack_speed`；怪物**不生成武器实体**（无身体容器），`equipment` 只作尸体掉落/视觉。武器 part 用 serde 解析、怪物模板用 Rust 常量数组，两边复用同一 `OnHitEffect` 类型；新 weapon part 使 items schema 升 **10**。实现顺序：迟缓 → 眩晕 → 流血；`weapon_on_hit_system` 接在 `apply_damage_system` 之后消费 `DamageTakenEvent`；`apply_on_hit_effects_system` 替换硬编码 Scorpion；效果挂载复用 `EffectDuration`/现有状态实体，不引入通用状态机；物种×效果免疫检查集中在一处 helper。
