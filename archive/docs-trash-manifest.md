# docs-trash-manifest — 文档治理的垃圾桶清单

> **用途：** 记录"删掉了什么、为什么删、等价的现在在哪"。没有这张表，`history` 分支
> 就是一堆干草——找得到提交，找不到你当初想要的那段话。

## 怎么把删掉的东西取回来

删除前的完整文档状态保存在两处（**同一次快照，内容一致**）：

```bash
# 一次性快照（不可变，推荐）：
git show docs-pre-governance:REFACTOR.md

# 分支形式（方便 checkout 出来对照整棵树）：
git checkout history -- REFACTOR.md     # 只取一个文件到工作区
git diff history -- REFACTOR.md         # 看治理前后的差异
```

- **tag** `docs-pre-governance` → 提交 `00b0e8f`（文档治理开始前的最后状态）
- **branch** `history` → 同一提交

> 为什么两个都要：tag 不会被误移动，适合当"不可变垃圾桶"；分支便于 `checkout` 与 `diff`。

## 原则：什么必须留下，什么可以删

| 留下（**永不删**） | 理由 |
|---|---|
| `LESSONS.md`（根 + 各 crate，全部条目） | 读者是 AI；每条都对应一次真实踩坑。删掉等于允许重犯 |
| `GAME.md` 的数值与标注 | 唯一的数值权威；`[⃞计算]/[⃞直觉]/[⃞试调]` 的标注是"为什么是这个数" |
| 绑定契约（现集中在 DESIGN `DsnX17`） | 冻结清单 / serde 只追加 / 确定性 / 边界 |
| `ISSUES.md` 的**待处理**区 | 未闭合问题就是待办 |
| `RULE.md` | 文档规则本身；AI 无权改，改动需用户批准 |

| 可以删（**先搬走结论**） | 处理方式 |
|---|---|
| 已完成阶段的过程记录 | 结论折进 DESIGN / ISSUES，本文件记一行"已完成（commit X）" |
| 与代码一一对应的规格复述（模块树、系统流程图） | 代码与 crate 文档已是权威；删除，留指针 |
| 被取代的设计条目 | 标 ~~已废弃~~ 并指向替代项（不直接删：保留"为什么当时那么想"） |
| 已修复但仍占大量篇幅的问题明细 | 压缩为一行表格项（id / 一句话 / 位置 / 教训），原文进垃圾桶 |
| 重复叙述（同一件事在 README、DESIGN、REFACTOR 各写一遍） | 只留一处权威，其余改成指针 |
